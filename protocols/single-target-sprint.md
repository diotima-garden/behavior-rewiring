# Protocol — Single-Target Sprint

A template. The running of it, and every log it produces, belong to the child grove — this
node holds no memory bank by design.

**What it is for:** converting one understood intention into reps, without the parallel
self-improvement collapse. One active target, a fixed window, a daily catch-log, and an
explicit decision at the end.

**Grounded in:** `principles.md` §2 (detection load is the budget), §3 (cue→response
pairs), §4 (substitute, don't suppress), §6 (nights are inside the protocol).

**Not original, and that is good news.** Its two load-bearing moves — train detection
first, then attach an incompatible response to the cue — are the core components of habit
reversal training, a clinical treatment with a meta-analysis behind it (`sources.md` §7,
d ≈ 0.80). The validated evidence is in body-focused repetitive behaviors under low
arousal, so this is convergence on the mechanism, not a licence to claim the same effect
for a social cue. Treat it as the nearest validated analogue and keep the ceiling
statement below honest.

---

## Shape

| | |
|---|---|
| Active targets | **Exactly one** |
| Passive supports | As many as you can arrange |
| Window | 30 days default; 45 if the cue is rare |
| Daily cost | One catch-log line. If it needs more, the protocol is wrong. |
| Ends with | A review and a ruling — extend, bank, or abandon |

## 1. Pick the target

Write it as one line with both halves present:

> **When** `<specific, detectable trigger>`, **I** `<one specified behavior>`.

Reject the target if any of these is true:

- **No cue.** It names a trait or a mood ("be less defensive"). Not trainable — §3.
- **No replacement.** It is a "stop doing X." The cue will still fire; give it an answer — §4.
- **The response isn't behavioral.** "Then I stay calm" is a state. "Then I say one
  sentence and stop" is a behavior.
- **You cannot reliably tell the cue happened.** Then the first sprint's target is
  *recognition* — log the cue, change nothing. That is a legitimate sprint and often the
  right first one.

Selection heuristic when several candidates compete: prefer the cue that genuinely occurs
*upstream of* several behaviors you want changed. State the shared cue out loud. Do not
reach for "train my general impulse control" instead — that is the one approach the
evidence rules out (`sources.md` §4).

## 2. Queue the rest

Everything else goes on a written waiting list in the grove, with its one-line
cue→response already drafted. Writing them down is what makes carrying one target
tolerable; the point is sequencing, not abstinence.

## 3. Add passive supports

Changes that remove or weaken the cue, requiring no in-the-moment catch: an artifact moved
out of reach, a notification off, a default setting changed, a commitment made in advance
to someone else. These do not count against the one-target limit — they are not detection
load. Stack them freely.

## 4. Run the catch-log

One line per day, in the child grove's own log. Minimum viable schema:

| Field | Note |
|---|---|
| Date | |
| Cue fired? | How many times you *noticed* it |
| Outcome | `caught+substituted` / `caught, old response anyway` / `noticed only afterwards` |
| Load | Rough sense of pressure at the time — the arousal axis matters (§5) |
| One line | What actually happened |

Two things to resist. **Don't add fields** — the log competes with the thing it measures.
And **count `noticed afterwards` as a win early on**: retrospective noticing is the first
sign detection is coming online, and a log that only rewards clean execution will record
nothing for two weeks and then get abandoned.

## 5. Protect the nights

Reps stabilize during sleep; a sprint run on broken sleep logs effort and banks less of it
(`sources.md` §3). So a sprint is daily and cannot be batched. If sleep collapses for a
stretch, note it in the log — it is confounding data, not a moral failing.

## 6. Review and rule

At the end of the window, read the log and write **one** of:

- **Extend** — catches are rising but the old response still often wins. Normal; 30 days is
  a dose, not a cure (§7).
- **Bank** — the substitution is now mostly automatic at low load. Move it to a passive
  watch and take the next target off the queue. Expect it to degrade if the context
  changes; habits are context-bound (`sources.md` §3).
- **Abandon or reframe** — the cue never fired often enough (pick a more frequent trigger),
  or you never detected it (go back to a recognition-only sprint), or the target was a
  trait in disguise.

Write the ruling down with its reason. A sprint whose outcome isn't recorded teaches the
next one nothing.

---

## Honest limits

- The sprint trains the rep. It does not promise automaticity in 30 days — the real spread
  is weeks to most of a year, and interception under social load is at the slow end (§7).
- Low-load catches do not predict high-load catches. That is the acquisition/performance
  split (§5), and it is why the `Load` column exists.
- A clean log is not evidence of change in the world. Only the world is.
